# 视频游乐场「生成结果」区 UI 设计

状态：已确认  
日期：2026-08-06  
范围：仅前端右侧「生成结果」面板的逻辑、布局与样式；后端历史 API / MinIO 转存不变。

## 1. 目标

右侧面板同时服务「当前创作」与「历史回看」，且二者**同等重要、互不抢戏**：

- 当前生成任务与历史记录出现在**同一卡片列表**
- 支持**多个任务同时进行**
- 刷新后仍可分页浏览并恢复进行中轮询
- 视觉与交互对齐项目表格分页习惯，避免自定义两套分页心智

## 2. 已锁定决策

| 决策点 | 结论 |
| --- | --- |
| 内容模型 | 单一列表：新提交与历史同列，按时间倒序（服务端 `ORDER BY id DESC`） |
| 卡片结构 | 同构：左侧参数，右侧结果（视频 / 进度 / 失败） |
| 播放器 | 每张成功卡片自带可播视频；不设上方独立大播放器 |
| 选中态 | **无**描边、无高亮、无「当前焦点」副本区 |
| 面板滚动 | 标题区固定；中间仅卡片滚动；底部分页栏固定 |
| 分页控件位置 | **全部在底栏**：总数 + 每页 + 首页/上页/页码/下页/末页 |
| 页大小 | `6 / 12 / 24`，localStorage 持久化 |
| 页码 | 可点选页码按钮；多页时用 `getPageNumbers` 省略（`…`），与 `DataTablePagination` 一致 |
| 官方组件 | 不直接复用绑死 TanStack Table 的 `DataTablePagination`；用相同 `Button` / `Select` 与 `getPageNumbers` 自建轻量底栏，视觉对齐 |

## 3. 面板信息架构

```
┌─ 生成结果 ──────────────────── [任务日志] ─┐
│ 最近生成 · N 进行中                         │  ← 顶栏固定（无「每页」）
├────────────────────────────────────────────┤
│ ┌──────────────┬─────────────────────────┐ │
│ │ 左：参数      │ 右：视频 / 进度 / 失败   │ │  ← 唯一滚动区
│ └──────────────┴─────────────────────────┘ │
│ …更多同构卡片…                              │
├────────────────────────────────────────────┤
│ 共 N · 每页 [6▾] · « ‹ 1 2 3 … 8 › »       │  ← 底栏固定
└────────────────────────────────────────────┘
```

### 3.1 删除（相对当前实现）

- 上方独立的 Task ID / Status / Progress / 大播放器区块
- 历史卡片的选中描边 / 浅底高亮
- 「每页」拆在顶栏、翻页拆在底栏的分离布局
- 「选中即焦点、自动滚入视口」作为主交互（无选中概念后不再需要）

### 3.2 卡片内容契约

左侧（来自 `properties.input` 快照，缺省时降级）：

- 模型名、模式（文生 / 首尾帧 / 参考等）、时长、分辨率/比例、提示词摘要、提交时间

右侧（按状态互斥）：

- `SUCCESS`：`<video controls>`，URL 优先用列表 DTO 的 `result_url`（含 MinIO 预签名）
- 进行中（`NOT_START` / `SUBMITTED` / `QUEUED` / `IN_PROGRESS` 等非终态）：进度文案 + spinner，不渲染播放器
- `FAILURE` / `FAILED`：失败原因
- 成功但无 URL：占位提示「视频地址不可用」

卡片**不是**按钮式「选中」控件；视频控件自身可交互，不需要整卡 click-to-select。

## 4. 逻辑与数据流

### 4.1 列表真相源

- `GET /api/task/self?task_type=video&p=&page_size=`
- React Query 分页；提交成功 / 任务终态后 `invalidate` 刷新

### 4.2 多任务并行

- 提交后乐观插入（或立即 invalidate）使新卡出现在列表顶部
- `useVideoGeneration` 可同时轮询多个 `task_id`
- 轮询结果写回列表中对应卡片的状态 / 进度 / `result_url`
- 顶栏「N 进行中」= 当前页（或已知 pending 集合）中非终态数量；以实现时取「本页非终态 + pending ids」的并集计数，避免误导

### 4.3 刷新恢复

- 首屏加载第一页后，对非终态任务恢复轮询
- localStorage 仅缓存未完成 `task_id` 做乐观恢复，不存完整历史

### 4.4 空态

- 无任何记录：中间区单一空文案「暂无生成记录」
- 不再同时出现「尚无进行中任务」+「尚无历史」两套空态

## 5. 组件拆分（建议）

| 组件 | 职责 |
| --- | --- |
| `VideoResultPanel` | 右侧面板壳：标题、顶栏、滚动区、底栏 |
| `VideoHistoryCard` | 单卡同构布局与状态右栏 |
| `VideoHistoryPagination` | 底栏：总数、每页、页码按钮；复用 `getPageNumbers` |
| `useVideoHistory` | 分页查询与 pageSize 持久化 |
| `useVideoGeneration` | 提交与多任务轮询（去掉「焦点选中」驱动 UI） |

`index.tsx` 不再渲染独立「当前任务详情」块；结果区只挂 `VideoResultPanel`。

## 6. 样式约束

- 沿用现有 Card：`border` + `ring-0` + `data-card-hover='false'`，避免 hover 位移裁切
- 历史卡片统一 `border-border`，**无** `border-primary` 选中态
- 底栏右对齐（或两端：左总数、右控件），窄屏允许换行，参考 `@container/pagination` 思路
- 文案全部走 i18n

## 7. 非目标（本设计不做）

- 「再来一次」回填表单（可后续加，卡片上暂不放入口）
- 列表内分组标题（进行中 / 已完成）
- 选中放大展开
- 新建历史表或改后端筛选契约

## 8. 验收标准

- [ ] 右侧无上方独立播放器 / Task ID 详情块
- [ ] 仅一份同构卡片列表；多进行中任务可同时显示进度
- [ ] 卡片无选中高亮
- [ ] 顶栏固定、列表滚动、底栏固定
- [ ] 底栏含：总数、每页 6/12/24、首页/上页/可点页码/下页/末页
- [ ] 刷新后历史仍在，进行中任务恢复轮询
- [ ] typecheck 与相关前端测试通过
