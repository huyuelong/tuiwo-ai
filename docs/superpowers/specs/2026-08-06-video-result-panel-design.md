# 视频游乐场「生成结果」区 UI 设计

状态：已确认（含 2026-08-06 卡片参数区 / 详情 / 参考媒体修订）  
日期：2026-08-06  
范围：右侧「生成结果」面板 UI；任务绑定参考媒体长期可访问（后端小改）；成片 MinIO 转存沿用既有设计。

## 1. 目标

右侧面板同时服务「当前创作」与「历史回看」，且二者**同等重要、互不抢戏**：

- 当前生成任务与历史记录出现在**同一卡片列表**
- 支持**多个任务同时进行**
- 刷新后仍可分页浏览并恢复进行中轮询
- 卡片左侧参数区条理清晰；「查看详情」可看全量参数与参考媒体
- 参考媒体对用户表现为长期可打开（object key + 再预签名 + 对象长期保留）
- 视觉与交互对齐项目表格分页习惯

## 2. 已锁定决策

| 决策点 | 结论 |
| --- | --- |
| 内容模型 | 单一列表：新提交与历史同列，按时间倒序 |
| 卡片结构 | 同构：左侧参数摘要，右侧成片 / 进度 / 失败 |
| 播放器 | 成功卡片右侧自带可播视频；无上方独立大播放器 |
| 选中态 | **无**描边 / 高亮 / 焦点副本 |
| 面板滚动 | 标题区固定；中间仅卡片滚动；底部分页栏固定 |
| 分页 | 底栏合并：总数 + 每页 6/12/24 + 首页/上页/页码/下页/末页（`getPageNumbers`） |
| 详情形态 | **右侧 Sheet** |
| 应用参数 | **本轮不做**，后续迭代 |
| 参考媒体长期访问 | **任务绑定转存**到 `media-task-assets/`，Input 持久化 object_key，展示时再预签名 |

## 3. 面板信息架构

```
┌─ 生成结果 ──────────────────── [任务日志] ─┐
│ 最近生成 · N 进行中                         │  ← 顶栏固定
├────────────────────────────────────────────┤
│ ┌──────────────┬─────────────────────────┐ │
│ │ 左：参数摘要  │ 右：成片 / 进度 / 失败   │ │  ← 唯一滚动区
│ └──────────────┴─────────────────────────┘ │
├────────────────────────────────────────────┤
│ 共 N · 每页 [6▾] · « ‹ 1 2 3 … 8 › »       │  ← 底栏固定
└────────────────────────────────────────────┘
```

点「查看详情」→ 右侧 Sheet（见 §5）。

### 3.1 删除（相对当前实现）

- 上方独立 Task ID / Status / Progress / 大播放器区块
- 卡片选中描边 / 浅底高亮
- 「每页」在顶、翻页在底的分离布局

## 4. 卡片左侧参数区（对照参考图，适配本项目）

自上而下：

1. **徽章行**
   - 任务 ID（截断展示，可复制完整 ID）
   - 状态徽章：已完成 / 进行中 / 失败（映射 SUCCESS / 非终态 / FAILURE）
   - 模式徽章：文生视频 / 首尾帧 / 参考生视频 等
2. **提示词**
   - 固定最多 **3 行**（`line-clamp-3`），超出省略号
   - 旁侧复制按钮（复制完整提示词）
3. **键值列表**（灰标签 + 正文）
   - 模型
   - 创作时间（`submit_time` / `created_at`）
   - 生成耗时（有 `finish_time` 则算差值，否则 `-`）
   - 时长/尺寸（如 `5秒 · 720P · 16:9`）
   - **不展示「创建者」**（游乐场均为本人）
4. **操作行**
   - 「查看详情」（本轮必做）
   - 「应用参数」按钮可先占位隐藏或灰显文案不进本轮；**本轮不实现回填逻辑**

### 4.1 右侧结果区

- `SUCCESS`：`<video controls>`，`result_url`（含成片预签名）
- 非终态：进度 + spinner
- 失败：失败原因
- 成功无 URL：占位「视频地址不可用」

卡片整卡**不是**选中控件；仅按钮与媒体控件可点。

## 5. 查看详情（Sheet）

使用项目已有 `Sheet`，从右侧滑出。

### 5.1 内容分区

1. 头：状态、模式、任务 ID（可复制）
2. 完整提示词（可复制，不截断）
3. 全部生成参数：模型、时长、分辨率、比例、音频、思考等（来自解析后的 Input 快照）
4. **参考媒体**（按类型分组，有则显示）
   - 首帧 / 尾帧
   - 参考图片
   - 参考视频
   - 参考音频
5. 成片（有 `result_url` 时）

### 5.2 媒体展示规则

- 优先用持久化的 **object_key** 向后端换取新的预签名 GET，再预览
- 仅有过期 URL、无 key：显示「媒体已失效」，不打断整页
- 图片缩略图；视频/音频用原生控件

## 6. 参考媒体长期可访问（后端）

### 6.1 问题

当前 complete 返回的 `get_url` 为约 24h 预签名；`Properties.Input` 若只存 URL，历史详情中参考媒体必然失效。对象若仍落在 `media-uploads/`（7 天生命周期），对象本身也会被删。

### 6.2 方案（已锁定：任务绑定转存）

提交任务成功并插入 `Task` 时（或紧随其后的异步步骤，但须在用户可查详情前完成关键路径）：

1. 从请求快照解析出本次引用的媒体（`metadata.input.media[].url` 等）
2. 将对应对象从 `media-uploads/...` **复制/提升**到  
   `media-task-assets/{userId}/{taskId}/{index}.{ext}`  
   （实现可用 CopyObject；失败则记日志，上游仍可用当时 URL 提交）
3. Input 快照中为每条媒体写入稳定字段，至少包含：
   - `object_key`（提升后的 key）
   - `type`（first_frame / last_frame / reference_image / …）
   - 可选：`content_type`、原始文件名
   - 可保留当时 `url` 作短期兼容，但**展示以 object_key 为准**
4. 列表/详情需要预览时：服务端或专用 API 按 object_key **重新 PresignGet**（仍约 24h，可反复签发）

前端提交体需能带上 `object_key`（表单已有 upload 资产的 key），避免后端只能从 URL 反推。

### 6.3 桶生命周期

| 前缀 | 用途 | 建议保留 |
| --- | --- | --- |
| `media-uploads/` | 未绑定任务的上传草稿 | **7 天** |
| `media-task-assets/` | 已绑定任务的参考媒体 | **长期**（建议 ≥ 成片保留，或与业务一致的 180/365 天；若产品要求「不过期」则不配过期规则） |
| `media-results/` | 成功成片 | **30 天**（可另议与 task-assets 对齐） |

对用户「URL 不过期」= **对象长期在 + 每次再预签名**，不是把预签名字符串写成永久链接。

### 6.4 旧数据

无 `object_key`、仅有过期 URL 的历史任务：详情媒体区降级提示，不报错、不阻塞成片播放。

## 7. 逻辑与数据流

### 7.1 列表

- `GET /api/task/self?task_type=video&p=&page_size=`
- React Query 分页；提交成功 / 终态后 invalidate

### 7.2 多任务

- 可同时轮询多个 task_id；更新写回列表对应卡片
- 顶栏「N 进行中」：本页非终态 ∪ pending ids

### 7.3 刷新恢复

- 首屏非终态恢复轮询；localStorage 仅缓存未完成 task_id

### 7.4 空态

- 无记录：单一「暂无生成记录」

### 7.5 详情媒体签发（实现选项，择一写清即可）

- **优选**：列表 DTO 不批量签发全部参考媒体；Sheet 打开时按 task 调轻量接口（或复用现有 media 预签名能力）批量换 GET
- 避免每次列表把所有参考媒体都预签名（成本与体积）

## 9. 样式约束

- 面板 Card：`border` + `ring-0` + `data-card-hover='false'`
- 历史卡片统一 `border-border`，无选中高亮
- 提示词 `line-clamp-3`
- 状态/模式用轻量徽章，颜色语义清晰且符合现有主题变量
- 文案全部 i18n

## 10. 非目标（本轮不做）

- **应用参数 / 再来一次**回填左侧表单
- 列表内「进行中 / 已完成」分组标题
- 选中放大展开
- 永久公开直链（破坏私有桶）
- 新建历史表
